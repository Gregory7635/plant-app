# ADR — Architecture Decision Records

## Проект: Веб-приложение для идентификации растений

Architecture Decision Records (ADR) фиксируют ключевые архитектурные решения, принятые в ходе разработки.

---

## ADR-001: Выбор архитектурного паттерна PCMEF

**Дата:** 2026-03-10  
**Статус:** Принято

### Контекст
Необходимо выбрать архитектурный паттерн для организации кода Spring Boot приложения. Рассматривались: классический трёхуровневый MVC, гексагональная архитектура, PCMEF.

### Решение
Принять паттерн **PCMEF** (Presentation–Control–Mediator–Entity–Foundation).

### Обоснование
- Соответствует требованиям курсового проекта
- Чёткое разделение ответственности между 5 слоями
- Естественно отображается на Spring Boot компоненты: Controllers → Control, Services → Mediator, Entities → Entity, Repositories → Foundation
- Направленные зависимости исключают циклические зависимости

### Последствия
Положительные: высокая тестируемость, понятная структура пакетов.  
Отрицательные: больше классов/интерфейсов по сравнению с простым MVC.

## ADR-002: Выбор базы данных PostgreSQL

**Дата:** 2026-03-10  
**Статус:** Принято

### Контекст
Необходимо выбрать СУБД для хранения пользователей, растений и истории идентификаций. Рассматривались: H2 (in-memory), MySQL, PostgreSQL.

### Решение
Использовать **PostgreSQL**.

### Обоснование
- Открытый исходный код, бесплатная лицензия
- Официальный образ в Docker Hub
- Полная поддержка Spring Data JPA / Hibernate
- Надёжная работа с JSON-полями (хранение дополнительных данных от Plant.id API)
- H2 отвергнут: нет persistence между перезапусками; MySQL отвергнут: PostgreSQL более стандартен в enterprise-среде

### Последствия
Положительные: надёжность, полный SQL, поддержка транзакций.  
Отрицательные: требует отдельного сервиса (решено через Docker Compose).

## ADR-003: Использование Spring Security для аутентификации

**Дата:** 2026-03-15  
**Статус:** Принято

### Контекст
Приложение требует регистрации, авторизации и разграничения доступа. Рассматривались: ручная реализация сессий, JWT, Spring Security.

### Решение
Использовать **Spring Security** с form-based аутентификацией и сессиями.

### Обоснование
- Встроен в Spring Boot, минимальная конфигурация
- Form-based login подходит для Thymeleaf веб-приложения
- BCrypt-хеширование паролей из коробки
- JWT отвергнут: избыточен для монолитного веб-приложения с сессиями

### Последствия
Положительные: безопасность, CSRF-защита, интеграция с Thymeleaf Security.  
Отрицательные: stateful сессии усложняют горизонтальное масштабирование (несущественно для текущего масштаба).

## ADR-004: Интеграция с Plant.id API через HTTP-клиент

**Дата:** 2026-03-20  
**Статус:** Принято

### Контекст
Идентификация растений требует внешнего ML-сервиса. Рассматривались: собственная ML-модель, Plant.id API, iNaturalist API.

### Решение
Использовать **Plant.id API** через `RestTemplate` / `HttpClient`.

### Обоснование
- Plant.id специализируется именно на растениях, точность >90%
- REST API с JSON — стандартная интеграция
- Бесплатный план достаточен для разработки и демонстрации
- Собственная модель отвергнута: требует большого датасета и GPU

### Последствия
Положительные: высокая точность без собственного ML.  
Отрицательные: зависимость от внешнего сервиса, платный план при масштабировании.

## ADR-005: Контейнеризация через Docker Compose

**Дата:** 2026-04-01  
**Статус:** Принято

### Контекст
Необходимо обеспечить воспроизводимое развёртывание. Рассматривались: ручная установка, Docker, Kubernetes.

### Решение
Использовать **Docker Compose** с двумя сервисами: `app` и `postgres`.

### Обоснование
- Одна команда `docker compose up --build` запускает всё окружение
- Kubernetes избыточен для одного микросервиса
- `Dockerfile` с multi-stage build уменьшает размер образа

### Последствия
Положительные: воспроизводимость, изоляция, простота CI/CD.  
Отрицательные: требует установки Docker на целевой машине.

## ADR-006: Выбор Thymeleaf для шаблонизации

**Дата:** 2026-03-10  
**Статус:** Принято

### Контекст
Необходимо выбрать технологию для серверного рендеринга HTML. Рассматривались: React SPA, Angular, Thymeleaf, JSP.

### Решение
Использовать **Thymeleaf** с **Bootstrap 5**.

### Обоснование
- Нативная интеграция со Spring Boot (автоконфигурация)
- Server-side rendering — SEO-friendly, нет проблем с CORS
- Bootstrap 5 даёт адаптивный UI без написания CSS с нуля
- React/Angular отвергнуты: усложняют стек, требуют отдельного сервера или build-пайплайна

### Последствия
Положительные: простота разработки, хорошая интеграция с Spring Security (CSRF токены).  
Отрицательные: AJAX-запросы требуют Fetch API вместо полноценного реактивного фреймворка.
