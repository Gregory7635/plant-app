# SWOT-анализ

## Проект: Веб-приложение для идентификации растений

| | Положительные | Отрицательные |
|---|---|---|
| **Внутренние** | Сильные стороны (S) | Слабые стороны (W) |
| **Внешние** | Возможности (O) | Угрозы (T) |

---

## S — Strengths (Сильные стороны)

| # | Фактор | Описание |
|---|---|---|
| S1 | Автоматическая идентификация | Использование Plant.id API обеспечивает высокую точность распознавания (>90% для распространённых видов) |
| S2 | Современный стек технологий | Java 17 + Spring Boot — промышленный стандарт, широкое сообщество, долгосрочная поддержка |
| S3 | Чёткая архитектура PCMEF | Разделение слоёв упрощает сопровождение и тестирование кода |
| S4 | Безопасность | BCrypt-хеширование паролей, Spring Security, защита от SQL-инъекций и XSS |
| S5 | История определений | Пользователь сохраняет все свои запросы — ценность данных накапливается со временем |
| S6 | REST API | Возможность интеграции с мобильными приложениями и сторонними сервисами |
| S7 | Docker-контейнеризация | Простота развёртывания на любой платформе без ручной настройки окружения |

---

## W — Weaknesses (Слабые стороны)

| # | Фактор | Описание |
|---|---|---|
| W1 | Зависимость от внешнего API | Работоспособность зависит от доступности Plant.id API; при сбое API идентификация недоступна |
| W2 | Платный API | Plant.id API имеет лимиты бесплатного плана; при масштабировании потребуется платная подписка |
| W3 | Ограниченный офлайн-режим | Без интернета невозможна идентификация растений |
| W4 | Отсутствие мобильного приложения | Только веб-интерфейс; мобильные пользователи работают через браузер |
| W5 | Покрытие тестами | Целевое покрытие 40% — достаточно для учебного проекта, но недостаточно для production |

---

## O — Opportunities (Возможности)

| # | Фактор | Описание |
|---|---|---|
| O1 | Рост интереса к экологии | Тренд на осознанное потребление и интерес к природе расширяет потенциальную аудиторию |
| O2 | Развитие ML-моделей | Появление более точных моделей распознавания позволит повысить качество идентификации |
| O3 | Мобильное приложение | Разработка React Native / Flutter приложения увеличит охват аудитории |
| O4 | Монетизация | Премиум-подписка с расширенной историей, уведомлениями о поливе, советами по уходу |
| O5 | Партнёрство | Интеграция с ботаническими садами, питомниками, образовательными платформами |
| O6 | Социальные функции | Добавление комментариев, лайков, сообщества любителей растений |

---

## T — Threats (Угрозы)

| # | Фактор | Описание |
|---|---|---|
| T1 | Конкуренция | Существуют аналоги: PlantNet, iNaturalist, Google Lens — крупные игроки с большой базой данных |
| T2 | Изменение условий API | Повышение цен или прекращение работы Plant.id API потребует миграции на альтернативу |
| T3 | Законодательство | Ужесточение требований к обработке персональных данных (GDPR, 152-ФЗ) |
| T4 | Безопасность данных | Атаки на веб-приложения требуют постоянного обновления защиты |
| T5 | Изменение алгоритмов Wikipedia | Нестабильность Wikipedia API может привести к потере описаний растений |

---

## Стратегии на основе SWOT

### SO (Сила + Возможности)
- Использовать REST API (S6) для создания мобильного приложения (O3)
- Применить надёжный стек (S2) для быстрого добавления социальных функций (O6)

### ST (Сила + Угрозы)
- Абстрагировать вызов Plant.id API за интерфейсом, чтобы упростить замену (S3, T2)
- Усилить безопасность Spring Security и регулярно обновлять зависимости (S4, T4)

### WO (Слабость + Возможности)
- Реализовать кэширование результатов идентификации для снижения зависимости от API (W1, O2)
- Повысить покрытие тестами до 70%+ при выходе в production (W5, O4)

### WT (Слабость + Угрозы)
- Внедрить резервный API (например, iNaturalist) на случай недоступности Plant.id (W1, T2)
- Реализовать GDPR-совместимое удаление данных пользователя (W5, T3)
